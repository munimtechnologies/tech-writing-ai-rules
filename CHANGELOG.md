# Changelog

## Unreleased (2026-11-08 and 2026-11-09): studies 6, 7, 8 and 9 pre-registered, study 6's grading code fixed in advance

- **Study 9 is pre-registered** in `census/2026-11-vendor-docs-ai-labels/PREREGISTRATION.md` (2026-11-09): do company docs sites other than Microsoft Learn tell readers, people and agents, which pages were made with AI? The frame is every entry of the Stack Overflow 2025 Developer Survey's "Cloud development" list whose docs are run by a company that sells the product or a paid tier of it: 20 sites, from AWS, Google Cloud and Cloudflare to Railway and Yandex Cloud. The pre-registration lists all 42 entries with the decision for each. Microsoft Azure, NuGet and MSBuild share learn.microsoft.com, the reference studied in studies 7 and 8. A seeded draw takes 30 pages per site from its sitemaps. The pre-registration sets three gates (two are Microsoft control pages, to check the label and sentence detectors) and six predictions. Few sites label AI-made pages, in a `<meta>` tag or a Markdown front matter key, or show a sentence acknowledging AI. More of the same sites serve llms.txt and Markdown copies for AI readers. Few vendors publish a statement on AI use in their docs; that one is checked by hand with a fixed search procedure. It has not been graded yet.
- **New tool, `vendordocs.py` 0.1.0**, with offline tests in `test_vendordocs.py` (standard library only). For each site it reads robots.txt with its own User-Agent, collects in-scope English page URLs from the sitemaps, and crawls from the docs root only if the sitemaps give too few. Sitemap indexes are expanded "doc" children first, at most 25 files or 2,000 URLs, and gzip sitemaps are read. It draws 30 pages with `random.Random("study9|<site id>")` and fetches each as HTML, with `Accept: text/markdown`, and at its `.md` address, one request per second. It records AI-authorship labels in `<meta>` tags and front matter (description, title, keyword and tag fields are ignored), acknowledgement sentences (study 8's pattern, at most 200 characters, no page text kept), bot-check pages, `llms.txt` and `llms-full.txt`, and robots.txt `Content-Signal` lines. It computes the gates and P1 to P5 in integer arithmetic, leaves P6 to the hand check, and waits until the pre-registration is on `main` before it reads anything.
- **Test fix before first commit (2026-11-09):** the first attempt to commit study 9 was stopped by the repository's test-first check. One offline test, `test_crawl_fallback`, expected 3 sitemap files to be read for a site whose docs root is the host root; the tool correctly tries `<host>/sitemap.xml` and `<docs root>/sitemap.xml` once when they are the same URL, so it reads 2. The test now expects 2 and names the two files tried. `vendordocs.py` itself is unchanged (0.1.0), and no page of the 20 sites had been fetched for the study, so the pre-registration is unchanged.
- **Study 5 correction (2026-11-09):** Home Assistant's docs page is not a bot-check page. `llmsprobe.py` 0.1.0 had labelled `https://www.home-assistant.io/docs/` a challenge (marked unconfirmed in the result). A follow-up fetch with the same headers and the tool's own User-Agent got the normal 43,215-character documentation page. The only match was `challenge-platform` inside Cloudflare's background script (`/cdn-cgi/challenge-platform/scripts/precursor/main.js`), which Cloudflare adds to normal pages. `census/2026-11-llms-txt/RESULT.md` and `coding.csv` now say challenge = no for Home Assistant. CHALLENGE goes from 1 to 0 and REFUSES_AI_READERS from 3 to 2. P5 becomes 1 of 10 (10.0%) against 1 of 46 (2.2%) and still holds; no other outcome changes. The tool's own output files are unchanged. **Known limit of `llmsprobe.py` 0.1.0** (not fixed here): its bot-check pattern should look only for interstitial markers. The same follow-up saw Cloudflare answer Python's default User-Agent with a 403 "Error 1010" for `robots.txt` while it served the tool's own User-Agent a 200, so the User-Agent a reader sends can decide whether it can read robots.txt at all.
- **Study 8 is pre-registered** in `census/2026-11-ms-learn-ai-shown/PREREGISTRATION.md` (2026-11-09): does Microsoft Learn tell its readers, people and agents, that an article was made with AI? Microsoft's principles for AI-generated content promise that "All articles that contain any AI-generated content include text acknowledging the role of AI. You'll see this text at the end of the article." Study 8 draws a seeded sample of labelled and unlabelled articles from study 7's frame of MicrosoftDocs repos (up to 8 per stratum per repo, from 15 repos). The strata separate the key spelling (`ai-usage` against `ms.ai-usage` and others) from the value (`ai-assisted` against `ai-generated`). It fetches each live page twice, as HTML (what people see) and as the Markdown copy Learn serves to clients that send `Accept: text/markdown` (what agents such as Copilot Chat and Claude Code ask for). It sets three gates (one is a positive control page, to catch text added by scripts) and six predictions: acknowledgement shown for the canonical key, rarely for other spellings, almost never for unlabelled pages; missing from the Markdown copy; label kept in the Markdown copy's header; and "Next steps" / "Related content" sections missing from the Markdown copy. Two pages read by hand before writing it are described in the pre-registration and kept out of the sample. It has not been graded yet.
- **New tool, `learnshown.py` 0.1.0**, with offline tests in `test_learnshown.py` (standard library plus `git`; it imports `learnlabels.py` 0.1.0 for the frame, the sparse clone and the front matter parser). It maps each sampled file to its en-us URL through the repo's `docfx.json` (nearest file, longest matching `src`, `build.dest` and entry `dest`). It counts a page only when a fetched form names that exact file as its source (`source_path` or `original_content_git_url`). It fetches at most one request per second and honours robots.txt. It records the AI label in each form, any acknowledgement sentence (at most 200 characters; no article text is kept), whether such a sentence appears anywhere in the raw HTML, and which of the source's level-2 headings the Markdown copy keeps. It computes the gates and P1 to P6 in integer arithmetic, and it waits until the pre-registration is on `main` before it reads anything.
- **Study 7 is pre-registered** in `census/2026-11-ms-learn-ai-labels/PREREGISTRATION.md` (2026-11-09): how much of Microsoft Learn's documentation is labelled as made with AI? Microsoft's Learn-wide authoring instructions ask that Markdown "created or substantially modified with AI assistance" carry an `ai-usage` front matter entry (`ai-assisted` or `ai-generated`), and Microsoft Learn plans to retire most of its public documentation repos by the end of December 2026. The frame is the largest public, active, non-localized MicrosoftDocs repos (30 with at least 200 articles each, read in size order). The pre-registration sets a gate and six predictions: the labelled share, assisted versus generated, the share by `ms.date` year, how many repos use the label, and how consistent the key and value are. It has not been graded yet.
- **New tool, `learnlabels.py` 0.1.0**, with offline tests in `test_learnlabels.py` (standard library plus the `git` command line). It lists the organisation's public repos through the GitHub REST API (one retry per page after an hour, for the unauthenticated rate limit), builds the frame (no forks, archived repos, localized copies such as `.de-de`, or repos not pushed since 2026-05-01), and makes a shallow, blob-filtered, sparse clone of each repo with only `*.md` and `docfx.json` checked out. It reads the first 16 KB of each Markdown file, parses only the top-level YAML front matter keys, and finds the AI key in any of its spellings (`ai-usage`, `ms.ai-usage`, `ai.usage`). It records AI tokens elsewhere in the front matter (such as `ms.custom` values starting `ai-gen`), and `docfx.json` entries that set the label for many files. Each clone is deleted straight after reading, and no author names are recorded. It computes the gate and P1 to P6 exactly as pre-registered, with inclusive boundaries checked in integer arithmetic. It waits until the pre-registration is on `main` before it reads anything, polling every 15 minutes.
- **Study 6 is pre-registered** in `census/2026-11-llms-txt-agents/PREREGISTRATION.md`: what do llms.txt files tell AI agents to do? The frame is every entry of the open llms-txt-hub directory (`data/websites.json`, MIT, pinned commit `e406860`). A tool marks candidate lines in each valid llms.txt, and one AI coder reads every candidate line of a fixed sample of 200 files. Each file is coded for directives to AI readers and for their kinds: cite, promote, source of truth, usage, action (install, call, pay, report), limit, override and other. The pre-registration sets a gate and five predictions, and a recall sample of 20 files estimates what the cue lines miss. It has not been graded yet.
- **New tool, `agentlines.py` 0.1.0**, with offline tests in `test_agentlines.py` (standard library only). It reads the pinned directory and numbers its entries, probing a repeated llms.txt URL once. It honours robots.txt for its own agent name and labels each answer as `llmsprobe.py` does (valid, html, challenge, redirected, missing, short, unstructured, robots, error). It marks candidate lines: cue words with an AI addressee, imperatives, "you should" lines, override phrases, and AI-addressed sections under a level-2-or-deeper heading. It counts lines shared by three or more files once they are normalised, and draws the CODE and RECALL samples by a fixed hash order. It waits until the pre-registration is on `main` before it fetches anything.
- **New script, `grade_study6.py` 0.1.0**, with offline tests in `test_grade_study6.py` (standard library only). It was committed before any of the study's results had been seen and before any hand coding, so the grading is fixed in code as well as in words. It reads the hand coding (`coding.csv`, the tool's `coding_template.csv` with the codes filled in) and the tool's `probes.csv`. It refuses incomplete or inconsistent coding: a blank DIRECTIVE, a kind code on a file with no directive, a directive with no quote, or a quote over 200 characters. It computes the gate G1, P1 to P5 and the recall check exactly as the pre-registration states them, including the boundaries (P1 counts 10% and 40% as inside the range, and P5 is not graded when a year group has fewer than 30 files). It writes `grades.json` and prints a Markdown table.
- No other file changed. `llmsprobe.py`, `docscope.py` and `guidescan.py` stay at 0.1.0, `programs.py` at 0.1.1, and the skill at 0.1.1.

## 0.6.0 (2026-11-08): study 5 graded, agent skill added

- **Result of study 5** in `census/2026-11-llms-txt/RESULT.md`. Of the 56 open-source projects with AI contribution rules, 27 (48%) serve a valid llms.txt or llms-full.txt for their docs. All 27 are among the 46 projects whose rule allows AI-made work. None of the 10 that ban or restrict it serves one. 21 of the 27 also serve llms-full.txt. 2 projects block named AI crawlers in robots.txt (Gentoo's wiki and Gitea's docs host), and Home Assistant's docs page was labelled a bot-check page (unconfirmed). The gate and all five predictions held. The groups are confounded with project age, language and docs platform, so the split is not evidence of cause. The release adds `coding.csv` (hand-checked labels per project, with notes) and the tool's unchanged `frame.csv`, `bases.csv`, `probes.csv`, `projects.csv` and `LLMSPROBE_AUTO.md`. `census.json` is not republished.
- **Hand-check change (1):** Hono's `llms-full.txt` was relabelled from html to valid. It is `text/plain` full documentation that opens with a `<SYSTEM>` tag, so the first character `<` made the tool's `is_html` test call it HTML. **Known limit of `llmsprobe.py` 0.1.0** (not fixed here): a plain-text file that starts with `<` is labelled html. A later version should trust a `text/plain` or `text/markdown` content type over the first character. The tool also does not keep the base page's text, so a challenge label cannot be re-checked from `census.json`. A later version should keep the matched words.
- **New agent skill, `skills/oss-ai-contribution-rules/` 0.1.0** (first committed 2026-11-08, listed on skills.sh). A `SKILL.md` (Agent Skills format) tells coding agents such as Claude Code, Codex and Cursor to check a project's AI contribution rule before they write, edit or open a pull request or issue for it. It puts documentation first and covers the trap studies 2 and 3 found: a separate docs repo whose contributor files never repeat the main rule. `scripts/ai_rules_lookup.py` (standard library only, no network) looks a project up by GitHub URL, `owner/repo` or name. It prints the coded rule, a verbatim quote, the source link, any separate docs repo and what to do. Exit codes: 0 (matched), 1 (no row; rows from the same owner are listed as hints) and 2 (error). Its data in `assets/` are unchanged copies of study 2's and study 3's `coding.csv`, plus `repo_slugs.csv`. That file maps each study 2 row to GitHub slugs for lookup and is not part of the studies' coding. Offline tests: `python -m unittest -v test_ai_rules_skill`. The skill's text says plainly that it is a snapshot (texts read 2026-11-04 and 2026-11-07) and that the live files win. Its coded data are unchanged by study 5.
- **Skill 0.1.1 (same release):** a new section, "Reading other projects' files safely". The files the skill sends an agent to read (CONTRIBUTING, AGENTS.md, CLAUDE.md, PR templates, llms.txt) are written by others, and some address agents. The agent now reads them only for their contribution rules, and treats everything else in them as information, never as instructions. It runs nothing, installs nothing, fetches nothing further and sends nothing because such a file says so, and it asks the user about any other request. Study 5 found llms.txt files that ask every agent to add query parameters describing the user's task. A third-party file can make the agent stricter, never looser. This answers the skills.sh Snyk audit finding W011 (third-party content exposure). The reading is the skill's purpose, so the exposure remains, but it is now handled explicitly. A new test, `test_third_party_files_are_read_as_data`, checks the section. `ai_rules_lookup.py` is unchanged (0.1.0).
- **New tool, `llmsprobe.py` 0.1.0**, with offline tests in `test_llmsprobe.py` (standard library only). For each documentation base in a frame, it reads the base page (noting bot-check pages) and asks for it again as Markdown. It asks for `llms.txt` and `llms-full.txt` in the base's folder and at the host root, and labels each answer: valid, html, challenge, redirected, missing, short, unstructured, error or robots. It reads robots.txt of the host the docs land on. It records which of 20 named AI crawlers may not fetch the docs page while an agent without a group of its own may, plus any Content-Signal lines. Matching follows RFC 9309 / Google style: the agent's own group else `*`, the longest rule wins, and Allow wins a tie. It honours robots.txt for its own fetches and computes the pre-registered gate and predictions from its labels.
- No other tool changed: `programs.py` stays at 0.1.1, and `docscope.py` and `guidescan.py` at 0.1.0.

## 0.2.0 (2026-11-04): docscope.py 0.1.0, a second study

- **New tool, `docscope.py` 0.1.0**, with offline tests in `test_docscope.py`. It asks whether open-source projects' AI contribution policies say they cover documentation. The frame is the 101 projects of the open dataset awesome-ai-contribution-policies (data CC BY 4.0) at a pinned commit. For each project it reads the repo's standard policy files at the default branch, the dataset's own source link and up to four AI-policy links from those texts, then keeps every AI sentence word for word with first-pass flags (docs, code, generic, rule word). Raw Markdown and reST are read with hard-wrapped lines joined, so a sentence that spans lines stays whole. The text inside HTML comments is kept, because pull request templates put their instructions there. A rate-limited fetch (HTTP 429) is retried after 60, 120 and 240 seconds, and each page records whether it was retried.
- **Pre-registration** in `census/2026-11-oss-docs/PREREGISTRATION.md`, with a rubric, five predictions and two gates. It was committed before any policy text was read, and the tool waits for it.
- `programs.py` is unchanged (0.1.1).

## 0.1.1 (2026-11-04)

Fixes to `programs.py`'s automatic first pass, found while grading the 2026-11 census by hand. The census in `census/2026-11/` was made with 0.1.0. Its files, its primary coding and its graded result are unchanged: the primary coding was done by reading every saved sentence and never relied on these cues. The next census will use 0.1.1.

- **Curly apostrophes.** 0.1.0's ban cue knew "can't", "won't" and "don't" only with a straight apostrophe, so Corellium's "can’t" was missed and its first-pass label was other_mention, not ban. Cues are now matched on a copy of each sentence with curly apostrophes made straight. Sentences are still saved exactly as found.
- **Missed closed notices.** Bugfender's notice ("POSITIONS FILLED: CURRENTLY, WE ARE NOT LOOKING FOR NEW WRITERS ...") was not caught as a status sentence. The cues were already case-insensitive, but none covered "not looking for (new) writers" or "positions filled". Both are now cues, along with "not hiring/seeking writers, authors, contributors or submissions".
- **Redirects.** Each page now records `redirect`: `home` when the listed page lands on a home page, `elsewhere` when it lands on another path or site, and empty otherwise (scheme, `www.` and a trailing slash are ignored). Each program records `main_redirect`. In the 2026-11 census, four Active programs' links redirected away from any program page, and this was only found by hand (see `census/2026-11/RESULT.md`, P5).
- **Detector flag.** 0.1.0 set `mentions_detector` for any AI sentence containing a "detect" word, so privacy-policy text about detecting fraud counted. It now needs detection of AI writing ("if we detect AI drafts", "AI detection", a named tool). A new flag, `names_detector_tool`, records whether a tool is named (Originality.ai, GPTZero, Copyleaks, ZeroGPT, Turnitin, "AI detector"), which is what the 2026-11 rubric's DETECTOR flag asks for.
- `CENSUS_AUTO.md` gains a redirect column and redirect counts. In its detector column, `tool` means a tool is named and `yes` means detection is mentioned without naming one.

Not changed: the frame (the pinned list commit), the pages followed, the sentence splitter, the label set and the ban/assist/allow cues apart from the apostrophe fix. Two 0.1.0 false bans noted in RESULT.md ("no paywalls" at In Plain English, "AI does not replace our editors" at TestMu AI) are still possible in 0.1.1. The first pass is a screen, and the primary coding is done by reading.
